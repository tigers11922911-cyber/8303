1

下書きを清書せいしょにうつす

新しいアプリは、まだ「下書きノート」にあるよ。プルリクエスト（おねがいの紙）をつくって、マージ（清書にうつす）しよう。

  1. 上のタブのPull requests（プルリクエスト）をクリック。
  2. 右の緑のNew pull requestをクリック。
  3. base: は main（清書）、compare: は claude/jolly-euler-wqi04e（下書き）をえらぶ。
  4. Create pull requestをクリック。題名はそのままでOK。もう一度 Create pull request。
  5. 2本指で下へスクロールして、緑のMerge pull request → Confirm mergeをクリック。
  6. むらさき色のMergedが出たら、せいこう！ 🎉

近道

倉庫のページに、黄色い帯とCompare & pull requestというボタンが出ていたら、それをクリックすると手順3までとばせるよ。

2

倉庫を「公開こうかい」にする

無料の GitHub Pages は、だれでも見られる「公開（Public）」の倉庫でしか使えないよ。倉庫の名前のとなりを見てみよう。

「Public」と書いてあったら、もう公開になっているよ。この手順はとばして、次の3へ進もう。

「Private」と書いてあったら、次の手順で公開にするよ。

  1. 上のタブのSettings（せってい）をクリック。
  2. いちばん下までスクロールして、赤いわくのDanger Zoneをさがす。
  3. Change visibility → Change to public をクリック。
  4. たしかめの画面が出るので、書いてあるとおりにクリックして（倉庫の名前 tigers11922911-cyber/8303 を入力することもあるよ）、公開にする。

公開にすると、せかいじゅうの人が中身を見られるよ

だから、倉庫にはひみつのものを入れない。今のアプリのファイルには、ひみつは入っていないので大丈夫だいじょうぶ。（APIキーと合言葉あいことばは、使う機械の中だけにあるよ）

5

直す・アップロードする

倉庫のファイルを新しくしてコミット（保存）すると、1〜3分でネットのアプリも新しくなるよ。やりかたは2つ。

A　文字をはりつけて直す

  1. 倉庫で、直したいファイルをクリック（例：narreji → index.html）。
  2. 右上のえんぴつ ✏️をクリック。
  3. 文字のところを1回クリックしてから、⌘＋A（ぜんぶえらぶ）→ delete（消す）→ ⌘＋V（新しい全文をはりつけ）。
  4. ⌘＋F で existing code をさがす。見つからなければOK。
  5. 緑のCommit changes…をクリックし、もう一度Commit changes。

B　ファイルごとアップロードする

Claude などからもらったファイルは、Finderの「ダウンロード」フォルダに入っているよ。

  1. GitHubで、入れたいフォルダを開く（例：narreji）。
  2. Add file → Upload files をクリック。
  3. Finderの「ダウンロード」から、ファイルをGitHubの点線のわくの中へドラッグする（クリックしたまま動かして、はなす）。
  4. 下の緑のCommit changesをクリック。
  5. アップロードしたファイルを開いて、⌘＋F で existing code がないか、たしかめる。

ファイルの名前に気をつけて

同じ名前（例：index.html）のファイルを入れると、上書きされるよ。Macが「index (1).html」のように名前を変えていたら、Finderでファイルをえらんで return をおし、index.html に直してからアップロードしてね。

8303 / narreji /
Drag files here to add them to your repositoryOr choose your files
Commit changes

ドラッグがうまくいかないときは、「choose your files」をクリックして、ファイルをえらんでもいいよ。

6

前の形にもどす

GitHubは、ぜんぶの保存ほぞんの記録をのこしているから、こわれても前の形にもどせるよ。

  1. こわれたファイルを開いて、右上のHistory（時計のマーク）をクリック。
  2. こわれる前の日時の記録をさがし、右の … → View file をクリック。
  3. Rawをクリック。文字だけの画面になったら、⌘＋A → ⌘＋C でぜんぶコピー。
  4. 今のファイルにもどって ✏️ → ⌘＋A → ⌘＋V → Commit changes。

Macにも、おまもりのコピーをとっておこう

ファイルを開いて、Raw のとなりの ⤓（Download raw file）をクリックすると、Macの「ダウンロード」フォルダに保存ほぞんできるよ。うまく動いているときに、ときどきとっておくと安心あんしん。

むずかしいときは、Claude に「〇〇のファイルを、こわれる前にもどして」とたのんでもいいよ。

こまったとき

「404」と出て開けない

公開したすぐあとは、まだ準備中じゅんびちゅう。3分くらいまってね。それでもだめなら、アドレスのまちがい（narreji のつづり、最後の /）と、Pagesの Branch が main になっているかを見よう。

直したのに、前のまま

1〜3分まってから ⌘＋R。それでも前のままなら、強い読みこみなおしをしよう。Safariは ⌥＋⌘＋R、Chromeは ⇧＋⌘＋R。

Settings が見つからない

おうちの人のアカウントでログインしているか見てね。画面が小さいと、タブが「…」の中にかくれていることもあるよ。

ファイルがドラッグできない

点線のわくの中で指をはなしてね。うまくいかないときは「choose your files」をクリックして、「ダウンロード」からえらぼう。

Merge pull request がおせない

「conflict（ぶつかり）」と出ていたら、同じところを2か所で直したということ。自分で直さずに、Claude にたのもう。

Actions に赤い ✗ が出た

公開の作業がうまくいかなかったしるし。少しまってから、もう一度コミットしてみてね。何回もつづくときは、赤い ✗ の画面を Claude に見せて相談そうだんしよう。

ネットに出すときの4つのやくそく

  • APIキー・パスワード・合言葉あいことばは、倉庫に入れない。
  • 名前・住所・学校・電話番号・顔の写真は、ネットに出さない。
  • わからないボタンは、クリックする前におうちの人に聞く。
  • ほかの人も使うMacでは、終わったらGitHubからログアウトする。
